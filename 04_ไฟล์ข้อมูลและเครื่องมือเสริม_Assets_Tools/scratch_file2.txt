บทคัดย่อ
ในระบบการบริหารจัดการสาธารณสุขของแผนกผู้ป่วยนอก (Outpatient Department: OPD) ปัญหาเชิงโครงสร้างที่สำคัญคือ "ช่องว่างของการรอคอย" (The Waiting Gap) ซึ่งเป็นช่วงเวลาระหว่างที่ผู้ป่วยผ่านการคัดกรองเบื้องต้นแล้วแต่ต้องนั่งรอคอยเพื่อเข้าพบแพทย์ ในกรณีที่ผู้ป่วยมีสภาวะวิกฤตแอบแฝง เช่น ภาวะช็อกที่ซ่อนเร้น (Shock Index > 0.9) โรคหลอดเลือดสมองขาดเลือดเฉียบพลัน (Acute Ischemic Stroke) หรือภาวะหัวใจหยุดเต้นเฉียบพลัน (Cardiac Arrest) การตรวจวัดสัญญาณชีพเพียงครั้งเดียว ณ จุดคัดกรองจะไม่สามารถตรวจจับการเปลี่ยนแปลงทางสรีรวิทยาที่อาจทรุดลงอย่างรวดเร็วได้ นอกจากนี้ ระบบจัดการคิวในโรงพยาบาลส่วนใหญ่ยังเป็นระบบคิวแบบคงที่ (Static Queue) ที่ไม่สามารถปรับเปลี่ยนตามความเร่งด่วนของอาการผู้ป่วยได้
โครงงานนี้นำเสนอการพัฒนาระบบ "อุปกรณ์สวมใส่เพื่อการติดตามสุขภาพและเว็บแอปเช็คคิวผู้ป่วยนอก" (Wearable Health Monitoring Device and Outpatient Queue Check Web Application) หรือ "Commlyzer-Health" โดยบูรณาการเทคโนโลยีอินเทอร์เน็ตของสรรพสิ่ง (IoT) และระบบสมองกลฝังตัว ฮาร์ดแวร์อุปกรณ์สวมใส่ใช้ไมโครคอนโทรลเลอร์ ESP32 ร่วมกับเซนเซอร์วัดสัญญาณชีพเชิงแสง (Photoplethysmography: PPG) ได้แก่ MAX32664 / MAX30102 สำหรับตรวจวัดอัตราการเต้นของหัวใจ (Heart Rate), ระดับออกซิเจนในเลือด (SpO2), และประมาณค่าความดันโลหิต (Blood Pressure Estimation) ผสานกับเซนเซอร์วัดความเร่งและไจโรสโคป 3 แกน MPU-6050 สำหรับการตรวจจับการเคลื่อนไหวและการหกล้ม (Multi-Stage Fall Detection Algorithm) ตัวอุปกรณ์มีอัลกอริทึมตรวจสอบคุณภาพสัญญาณ (Signal Quality Index: SQI) และการตรวจจับการแนบสนิทของเซนเซอร์กับผิวหนัง (Contact Detection) เพื่อป้องกันค่าหลอกอันเกิดจาก Motion Artifacts ข้อมูลจะถูกประมวลผลและส่งผ่าน Wi-Fi ขึ้นสู่ระบบคลาวด์ Firebase และแสดงผลบน Web Application ที่พัฒนาด้วย Next.js, React และ Tailwind CSS แบบเรียลไทม์ พร้อมระบบจัดลำดับความเร่งด่วนของคิวตรวจ (Dynamic Triage Queue) และระบบแจ้งเตือนสภาวะวิกฤตสู่พยาบาลทันที
ผลการทดสอบพบว่า อุปกรณ์สวมใส่ต้นแบบมีความคลาดเคลื่อนในการตรวจวัดสัญญาณชีพเฉลี่ยไม่เกิน ±3.5% เมื่อเทียบกับอุปกรณ์ทางการแพทย์มาตรฐาน (อยู่ในเกณฑ์ยอมรับได้ไม่เกิน ±10%) อัลกอริทึมการตรวจจับการหกล้มแบบสเตตแมชชีนหลายขั้นตอนร่วมกับคะแนนความเชื่อมั่น (Confidence Scoring) สามารถจำแนกการหกล้มจริงออกจากการเคลื่อนไหวประจำวัน เช่น การโยนอุปกรณ์ การปรบมือ หรือการนั่งเร็ว ได้อย่างแม่นยำ โดยมีอัตรา False Alarm 0% ในการเคลื่อนไหวทั่วไป ระบบเครือข่ายมีค่าความหน่วงเฉลี่ย (Latency) ในการอัปเดตข้อมูลขึ้นหน้าจอ 3.2 วินาที และแบตเตอรี่สามารถทำงานต่อเนื่องได้ 6–8 ชั่วโมงต่อการชาร์จ 1 ครั้ง โครงงานนี้จึงเป็นนวัตกรรม Smart Healthcare ที่ช่วยยกระดับความปลอดภัยของผู้ป่วยนอกและเพิ่มประสิทธิภาพในการดูแลรักษาของบุคลากรทางการแพทย์อย่างแท้จริง

ABSTRACT
In modern healthcare administration within Outpatient Departments (OPD), a significant structural vulnerability is the "waiting gap"—the unmonitored duration between initial triage and physician consultation. When patients develop occult hemodynamically unstable conditions, such as occult shock (Shock Index > 0.9), acute ischemic stroke, or sudden cardiac arrest, a single static vital sign reading at admission fails to capture rapid physiological deterioration. Furthermore, conventional hospital queue systems operate statically and cannot adapt to fluctuating patient clinical severity.
This project introduces a comprehensive "Wearable Health Monitoring Smartwatch and Outpatient Queue Tracking Web Application" (Commlyzer-Health) leveraging Internet of Things (IoT) edge computing. The wearable device utilizes an ESP32 microcontroller integrated with optical Photoplethysmography (PPG) sensors (MAX32664 / MAX30102) for continuous Heart Rate (HR), Blood Oxygen Saturation (SpO2), and cuffless Blood Pressure (BP) estimation, complemented by an MPU-6050 6-axis IMU for sequential Multi-stage Fall Detection. Robust Signal Quality Index (SQI) and skin-contact detection filters are embedded to suppress motion artifacts. Telemetry data is encapsulated into JSON payloads and transmitted via Wi-Fi to a Firebase cloud database, powering a responsive real-time web dashboard engineered with Next.js, React, and Tailwind CSS. The system enables healthcare staff to continuously monitor patients, dynamically prioritize clinical queues, and receive instantaneous emergency alerts.
Experimental evaluations demonstrate that vital sign measurement errors remain strictly below ±3.5% compared to standard clinical benchmarks. The multi-stage fall detection algorithm successfully discriminates true falls from common daily activities (e.g., clapping, vigorous arm swinging, tossing, or rapid sitting) with a 0% false alarm rate in non-fall tests. Telemetry data exhibits an average latency of 3.2 seconds with automatic offline buffering upon network failure, and the device operates continuously for 6–8 hours per charge. This innovation delivers a scalable smart healthcare solution, mitigating clinical risks during outpatient waiting intervals and optimizing hospital workflows.
Keywords: Wearable Device, Vital Signs Monitoring, Fall Detection, Internet of Things (IoT), Outpatient Queue System, Smart Healthcare, ESP32, MAX32664, Next.js

บทที่ 1บทนำ
1.1 ความเป็นมาและความสำคัญของปัญหา
ในยุคปัจจุบัน การบริหารจัดการระบบบริการสาธารณสุขในโรงพยาบาล โดยเฉพาะแผนกผู้ป่วยนอก (Outpatient Department: OPD) ต้องเผชิญกับความท้าทายอย่างยิ่งจากจำนวนผู้เข้ารับบริการที่หนาแน่น ประกอบกับสังคมไทยและสังคมโลกได้ก้าวเข้าสู่ "สังคมผู้สูงอายุโดยสมบูรณ์" (Aged Society) ซึ่งส่งผลให้มีผู้ป่วยกลุ่มเปราะบางและผู้ป่วยโรคเรื้อรัง (Non-Communicable Diseases: NCDs) เช่น โรคความดันโลหิตสูง โรคเบาหวาน และโรคหัวใจ เข้ารับบริการในแต่ละวันเป็นจำนวนมหาศาล
ปัญหาเชิงโครงสร้างที่เกิดขึ้นอย่างต่อเนื่องและเป็นจุดวิกฤตของระบบการรักษาพยาบาล คือปรากฏการณ์ที่เรียกว่า "ช่องว่างของการรอคอย" (The Waiting Gap) ซึ่งหมายถึงช่วงเวลาหลังจากที่ผู้ป่วยผ่านจุดคัดกรองเบื้องต้น (Initial Triage Desk) แล้ว ต้องนั่งรอเรียกคิวเพื่อเข้าพบแพทย์ในห้องตรวจ หรือรอการตรวจทางห้องปฏิบัติการเพิ่มเติม ช่วงเวลาการรอคอยนี้อาจกินเวลาตั้งแต่หลายสิบนาทีไปจนถึงหลายชั่วโมง ในขณะที่เจ้าหน้าที่พยาบาลและบุคลากรทางการแพทย์มีจำนวนจำกัด ทำให้ไม่สามารถเดินตรวจวัดสัญญาณชีพของผู้ป่วยทุกคนที่นั่งรออยู่ในบริเวณโถงพักคอยได้อย่างต่อเนื่อง
ความเสี่ยงร้ายแรงที่แฝงอยู่ในช่องว่างของการรอคอยนี้ คือ "การเกิดภาวะวิกฤตทางสรีรวิทยาเฉียบพลันโดยไม่แสดงอาการเตือนที่ชัดเจนภายนอก" (Occult Hemodynamic Deterioration) ตัวอย่างเช่น:
📌 หลักฐานเชิงประจักษ์ทางการแพทย์และความสำคัญของเวลาวิกฤต
• ภาวะช็อกที่ซ่อนเร้น (Occult Shock): ประเมินได้จากค่าดัชนีช็อก (Shock Index: SI = Heart Rate / Systolic Blood Pressure) ซึ่งงานวิจัยของ Rady et al. (1994) [1] พบว่าผู้ป่วยที่มีค่า SI > 0.9 มีความสัมพันธ์อย่างมีนัยสำคัญกับการเกิดภาวะวิกฤตที่ต้องได้รับการช่วยชีวิตทันที แม้สัญญาณชีพภายนอกจะดูปกติ
• โรคหลอดเลือดสมองเฉียบพลัน (Acute Ischemic Stroke): มีช่วงเวลา "นาทีทอง" (Golden Period) ที่จำกัดมาก งานวิจัยเชิงปริมาณของ Saver (2006) [2] ระบุว่า ทุก 1 นาทีที่สมองขาดเลือดล่าช้า ผู้ป่วยจะสูญเสียเซลล์ประสาทสมองถึง 1.9 ล้านเซลล์ และสมองจะเสื่อมถอยเทียบเท่ากับเวลา 3.6 ปี
• ภาวะหัวใจหยุดเต้นเฉียบพลัน (Cardiac Arrest): ข้อมูลจากสมาคมโรคหัวใจแห่งอเมริกา (AHA) และ Larsen et al. (1993) [3] ระบุว่า โอกาสรอดชีวิตของผู้ป่วยจะลดลง 7–10% ในทุกๆ 1 นาทีที่ผ่านไปหากไม่ได้รับการช่วยฟื้นคืนชีพ (CPR)
• สถิติจากองค์การอนามัยโลก (WHO) [4]: โรคระบบหัวใจและหลอดเลือดเป็นสาเหตุการเสียชีวิตอันดับหนึ่งของโลก คร่าชีวิตผู้คนถึง 17.9 ล้านคนต่อปี การวัดสัญญาณชีพเพียงครั้งเดียวตอนลงทะเบียนจึงไม่เพียงพออย่างยิ่ง
นอกจากปัญหาด้านสรีรวิทยาแล้ว ระบบการจัดการลำดับคิวในโรงพยาบาลส่วนใหญ่ยังเป็น "ระบบคิวแบบคงที่" (Static Queue System) ซึ่งทำงานเรียงลำดับคิวตามเวลาที่มาก่อนหลัง (FIFO) หรือตามหมายเลขบัตรคิวที่พิมพ์จากกระดาษ โดยระบบไม่รับรู้ว่าผู้ป่วยหมายเลขคิวดังกล่าวกำลังเกิดอาการวิกฤต มีระดับออกซิเจนในเลือดลดต่ำลง หรือเกิดการหกล้มหมดสติในห้องน้ำหรือไม่
ด้วยเหตุนี้ คณะผู้จัดทำจึงได้นำเสนอการพัฒนาระบบ "อุปกรณ์สวมใส่เพื่อการติดตามสุขภาพและเว็บแอปเช็คคิวผู้ป่วยนอก" (Wearable Health Monitoring Device and Outpatient Queue Check Web Application) หรือในชื่อระบบ "Commlyzer-Health" โดยผสานเทคโนโลยีอินเทอร์เน็ตของสรรพสิ่ง (IoT) และระบบสมองกลฝังตัว เพื่อเปลี่ยนบทบาทของผู้ป่วยจากการนั่งรออย่างไร้การติดตาม ให้กลายเป็นผู้ป่วยที่ได้รับการเฝ้าระวังทางสรีรวิทยาแบบเรียลไทม์อย่างเป็นระบบ
1.2 วัตถุประสงค์ของโครงงาน
• เพื่อออกแบบและพัฒนาอุปกรณ์สวมใส่ต้นแบบ (Wearable Smartwatch Prototype) ที่สามารถตรวจวัดสัญญาณชีพพื้นฐาน ได้แก่ อัตราการเต้นของหัวใจ (Heart Rate), ระดับความอิ่มตัวของออกซิเจนในเลือด (SpO2), และประมาณค่าความดันโลหิต (Blood Pressure Estimation) โดยมีค่าความคลาดเคลื่อนไม่เกิน ±10% เมื่อเทียบกับอุปกรณ์มาตรฐานทางการแพทย์
• เพื่อพัฒนาอัลกอริทึมการตรวจจับการหกล้ม (Multi-Stage Fall Detection Algorithm) และการตรวจสอบคุณภาพสัญญาณ (Signal Quality & Contact Detection) บนไมโครคอนโทรลเลอร์ ESP32 เพื่อลดอัตราการแจ้งเตือนผิดพลาด (False Alarm)
• เพื่อพัฒนาเว็บแอปพลิเคชันแดชบอร์ด (Web Application Dashboard) ด้วย Next.js และ Firebase สำหรับแสดงผลข้อมูลสัญญาณชีพแบบ Real-time จัดลำดับความเร่งด่วนของคิวตรวจ (Dynamic Queue Prioritization) และแจ้งเตือนแพทย์/พยาบาลเมื่อพบสภาวะวิกฤต
• เพื่อพัฒนากระบวนการใช้งานแบบ On-site ที่มีพยาบาลหรือเจ้าหน้าที่เป็นผู้ช่วยในการสวมใส่และดูแลระบบ สำหรับผู้สูงอายุที่ไม่คล่องแคล่วในการใช้งานสมาร์ตโฟนด้วยตนเอง
1.3 สมมติฐานและแนวคิดการแก้ปัญหา
• การประมวลผลสัญญาณชีพ ณ แหล่งกำเนิด (Edge Computing บน ESP32) ร่วมกับการกรองสัญญาณรบกวนจากการเคลื่อนไหว (Motion Artifacts) จะช่วยให้อุปกรณ์สวมใส่บริเวณข้อมือสามารถให้ค่าสัญญาณชีพที่มีเสถียรภาพและเชื่อถือได้สำหรับการคัดกรองเบื้องต้น
• การตรวจจับการหกล้มโดยพิจารณาลำดับเหตุการณ์ต่อเนื่อง (Multi-Stage Sequence: Normal Motion → Free Fall → Impact → Orientation Change → Post-Fall Inactivity) ร่วมกับการให้คะแนนความเชื่อมั่น (Confidence Scoring) จะสามารถลด False Positive จากกิจกรรมประจำวัน เช่น การโยนของ หรือการแกว่งแขน ได้อย่างมีนัยสำคัญ
• การเชื่อมโยงข้อมูลสุขภาพแบบเรียลไทม์เข้ากับระบบคิวผู้ป่วย จะช่วยให้พยาบาลสามารถปรับลำดับการเข้าพบแพทย์ตามความวิกฤตของสัญญาณชีพจริง (Dynamic Clinical Triage) ลดอัตราการเสียชีวิตและภาวะแทรกซ้อนในโรงพยาบาลได้
1.4 ขอบเขตของโครงงาน
1.4.1 ขอบเขตด้านฮาร์ดแวร์ (Hardware Scope)
• อุปกรณ์สวมใส่รองรับการใช้งาน 1 คน ต่อ 1 อุปกรณ์ ในรูปแบบนาฬิกาข้อมือ (Smartwatch)
• ใช้ไมโครคอนโทรลเลอร์ 32-bit ตระกูล ESP32 (เช่น ESP32-C3 / XIAO-ESP32-C3 / ESP32-S3) เป็นหน่วยประมวลผลหลัก
• เซนเซอร์ตรวจวัดสัญญาณชีพ: ใช้โมดูล Optical PPG Sensor (MAX32664 / MAX30102 / MAX30100) สำหรับตรวจวัด Heart Rate, SpO2 และประเมินค่า BP
• เซนเซอร์ตรวจจับการเคลื่อนไหว: ใช้โมดูล 6-axis IMU (MPU-6050) สำหรับตรวจจับความเร่งและมุมการเอียง
• หน้าจอแสดงผล: จอกลม Round LCD ขนาด 1.28 นิ้ว (ความละเอียด 240x240 พิกเซล, Driver GC9A01) หรือจอ OLED 1.3 นิ้ว (I2C Address 0x3C)
• แหล่งพลังงาน: แบตเตอรี่ Li-Po 3.7V (500–800 mAh) พร้อมวงจรชาร์จและระบบป้องกันความปลอดภัย (PTC Fuse / MCP73871)
• การสื่อสาร: ส่งข้อมูลผ่าน Wi-Fi 2.4 GHz (และรองรับ BLE สำหรับการกำหนดค่า)
1.4.2 ขอบเขตด้านซอฟต์แวร์และระบบคลาวด์ (Software & Cloud Scope)
• เฟิร์มแวร์อุปกรณ์: พัฒนาด้วยภาษา C/C++ บน Arduino IDE / ESP-IDF ด้วยโครงสร้าง Modular Architecture
• ระบบฐานข้อมูลคลาวด์: ใช้ Firebase (Cloud Firestore และ Realtime Database) สำหรับจัดเก็บข้อมูลแบบเรียลไทม์
• เว็บแอปพลิเคชัน: พัฒนาด้วย Next.js Framework ร่วมกับ React และ Tailwind CSS รองรับการแสดงผลแบบ Responsive
• ฝั่งผู้ป่วย: แสดงหมายเลขคิว, สถานะห้องตรวจ, ค่าสัญญาณชีพปัจจุบัน, และปุ่มกดฉุกเฉิน (Emergency Call 1669)
• ฝั่งพยาบาล/แพทย์: แสดง Overview Dashboard รายชื่อผู้ป่วยทั้งหมด, จัดลำดับความวิกฤตของคิว (Critical / High / Medium / Low), และระบบเสียง/ป้ายเตือนเมื่อค่าสัญญาณชีพวิกฤตหรือเกิดการหกล้ม
1.5 ข้อจำกัดของโครงงาน (Limitations)
• การตรวจวัดสัญญาณชีพจากเซนเซอร์เชิงแสง (PPG) บริเวณข้อมือ เป็นการตรวจวัดเพื่อ "การคัดกรองเบื้องต้นและการเฝ้าระวังแนวโน้ม (Trend Monitoring)" เท่านั้น ไม่สามารถนำไปใช้ทดแทนการวินิจฉัยโรคขั้นเด็ดขาดทางการแพทย์ได้ 100% บุคลากรทางการแพทย์ยังคงต้องใช้เครื่องมือมาตรฐานยืนยันซ้ำ
• อุปกรณ์เป็นชุดต้นแบบวิจัย (Research Prototype) เหมาะสำหรับการใช้งานในสภาพแวดล้อมปกติ (อุณหภูมิห้อง ไม่กันน้ำ และหลีกเลี่ยงการกระแทกรุนแรง)
• การส่งข้อมูลขึ้นระบบคลาวด์แบบเรียลไทม์จำเป็นต้องอยู่ในพื้นที่ที่มีสัญญาณเครือข่าย Wi-Fi ที่เสถียร
1.6 ประโยชน์ที่คาดว่าจะได้รับ
• โรงพยาบาลได้ระบบเฝ้าระวังผู้ป่วยนอกแบบเรียลไทม์ ช่วยปิดช่องว่างของการรอคอยและลดความเสี่ยงการเสียชีวิตจากภาวะวิกฤตเฉียบพลัน
• ผู้ป่วยและญาติมีความอุ่นใจ ลดความวิตกกังวลระหว่างรอรับบริการ สามารถตรวจสอบลำดับคิวและสัญญาณชีพของตนเองได้ตลอดเวลา
• ลดภาระงานและความตึงเครียดของบุคลากรทางการแพทย์ในการเดินตรวจวัดสัญญาณชีพซ้ำๆ และช่วยให้การบริหารจัดการคิวตรวจมีประสิทธิภาพสูงสุด
• ได้ชุดความรู้และต้นแบบระบบฮาร์ดแวร์ IoT ทางการแพทย์ (Smart Healthcare) ที่ออกแบบบนพื้นฐานสรีรวิทยาจริงและพร้อมต่อยอดสู่เชิงพาณิชย์
บทที่ 2ทฤษฎีและงานวิจัยที่เกี่ยวข้อง
การพัฒนาระบบติดตามสุขภาพผู้สูงอายุและผู้ป่วยนอกแบบครบวงจร จำเป็นต้องอาศัยการบูรณาการองค์ความรู้หลากหลายสาขา ทั้งด้านสรีรวิทยาการแพทย์ การประมวลผลสัญญาณชีวภาพ (Biomedical Signal Processing) วิศวกรรมระบบสมองกลฝังตัว และเทคโนโลยีเครือข่ายคลาวด์ โดยในบทนี้จะนำเสนอทฤษฎีและงานวิจัยที่เกี่ยวข้องตามลำดับหัวข้อต่อไปนี้
2.1 สรีรวิทยาและสัญญาณชีพพื้นฐาน (Vital Signs & Clinical Triage)
สัญญาณชีพ (Vital Signs) เป็นตัวชี้วัดสภาวะการทำงานของระบบสำคัญในร่างกาย ได้แก่ ระบบหัวใจและหลอดเลือด ระบบทางเดินหายใจ และการควบคุมอุณหภูมิ โดยมีเกณฑ์มาตรฐานทางการแพทย์ดังแสดงในตารางที่ 2.1
พารามิเตอร์สัญญาณชีพ
ค่าปกติในผู้ใหญ่
เกณฑ์สภาวะวิกฤต (Alert)
ความสำคัญทางคลินิก

2.2 หลักการทำงานของเซนเซอร์เชิงแสง (Photoplethysmography: PPG)
Photoplethysmography (PPG) เป็นเทคนิคการตรวจวัดการเปลี่ยนแปลงของปริมาตรเลือดในหลอดเลือดฝอยใต้ผิวหนังโดยใช้แสง เซนเซอร์ PPG จะประกอบด้วยตัวเปล่งแสง (LEDs) สองความยาวคลื่น ได้แก่ แสงสีแดง (Red Light ความยาวคลื่น ~660 nm) และแสงอินฟราเรด (Infrared Light ความยาวคลื่น ~880–940 nm) ร่วมกับตัวตรวจจับแสง (Photodetector: PD)
หลักการทำงานอิงตามกฎของ Beer-Lambert Law เมื่อหัวใจบีบตัว ปริมาตรของเม็ดเลือดแดงในหลอดเลือดจะเพิ่มขึ้น ทำให้การดูดกลืนแสงเพิ่มขึ้น สัญญาณ PPG จึงประกอบด้วย 2 ส่วนหลักคือ: (1) ส่วนประกอบกระแสสลับ (AC Component) เกิดจากจังหวะการเต้นของหัวใจ และ (2) ส่วนประกอบกระแสตรง (DC Component) เกิดจากการดูดกลืนแสงของเนื้อเยื่อ กระดูก และเลือดที่อยู่นิ่ง
การคำนวณค่าความอิ่มตัวออกซิเจนในเลือด (SpO2) คำนวณจากอัตราส่วน Ratio of Ratios (R):
$$R = \frac{(AC_{Red} / DC_{Red})}{(AC_{IR} / DC_{IR})}$$
$$\text{SpO}_2 = A - B \times R$$
โดยที่ A และ B เป็นค่าสัมประสิทธิ์การปรับเทียบเชิงเส้น (โดยทั่วไป $A \approx 110, B \approx 25$ ขึ้นอยู่กับโมดูลเซนเซอร์และการออกแบบทางแสง)
2.3 ความท้าทายของเซนเซอร์ Optical บริเวณข้อมือและการแก้ปัญหา
การตรวจวัดสัญญาณ PPG บริเวณข้อมือ (Wrist-based PPG) มีความท้าทายและความซับซ้อนสูงกว่าการวัดที่ปลายนิ้ว (Finger-clip) อย่างมาก เนื่องจากบริเวณข้อมือมีชั้นผิวหนังที่หนากว่า มีเส้นเอ็น กระดูก และหลอดเลือดอยู่ลึกกว่า อีกทั้งข้อมือเป็นส่วนที่มีการขยับและเคลื่อนไหวอยู่ตลอดเวลา
📌 ปัจจัยรบกวนและแนวทางการแก้ปัญหาในโครงงานนี้
• สัญญาณรบกวนจากการเคลื่อนไหว (Motion Artifacts): การแกว่งแขน การเดิน หรือการสั่นสะเทือนจะทำให้เนื้อเยื่อขยับ เกิดสัญญาณหลอกในความถี่ใกล้เคียงกับจังหวะหัวใจ แก้ไขโดยใช้ MPU-6050 ตรวจจับ Motion Level หากพบว่าเคลื่อนไหวสูง ระบบจะปรับสถานะ Signal Quality เป็น POOR และไม่นำค่ามาคำนวณ
• แสงสว่างภายนอกรบกวน (Ambient Light Interference): แสงจากหลอดไฟฟลูออเรสเซนต์หรือแสงแดดที่ลอดผ่านช่องว่างสายรัดจะรบกวน Photodetector แก้ไขโดยการออกแบบฝาครอบเซนเซอร์ด้วยวัสดุทึบแสงสีดำ (Black Light Shielding) แนบชิดกับผิวหนัง
• การตรวจจับการแนบสนิทของเซนเซอร์ (Skin-Contact Detection): หากผู้ป่วยถอดอุปกรณ์ออก เซนเซอร์ Optical อาจอ่านค่าสัญญาณรบกวนในอากาศแล้วคำนวณเป็นค่า HR/SpO2 ลวงได้ ระบบจึงต้องมีอัลกอริทึมตรวจสอบค่าความแรงแสงสะท้อนต่ำสุด (Raw IR Threshold) หากต่ำกว่าเกณฑ์จะตัดเข้าสู่สถานะ NO_CONTACT ทันที
2.4 ทฤษฎีการตรวจจับการหกล้ม (Multi-Stage Fall Detection Algorithms)
การตรวจจับการหกล้ม (Fall Detection) ถือเป็นฟังก์ชันความปลอดภัยสูงสุดของระบบ อุปกรณ์สวมใส่โดยทั่วไปที่ใช้เพียง "เกณฑ์ความเร่งเดียว" (Single Threshold Acceleration > 2.5G) จะก่อให้เกิดการเตือนผิดพลาด (False Positives) เป็นจำนวนมาก เช่น เมื่อผู้ใช้ตบมือ โยนของ นั่งลงอย่างแรง หรือแกว่งแขนกระแทกโต๊ะ
ในโครงงานนี้ คณะผู้จัดทำได้ออกแบบอัลกอริทึมการตรวจจับการหกล้มแบบลำดับขั้นตอนต่อเนื่อง (Sequential Multi-Stage State Machine) ร่วมกับชุดตรวจวัดความเร่งและไจโรสโคป MPU-6050 โดยคำนวณค่าขนาดความเร่งรวม (Signal Magnitude Vector: SMV):
$$\text{SMV} = \sqrt{a_x^2 + a_y^2 + a_z^2}$$
ลำดับสเตตแมชชีนของการหกล้มจริง (Genuine Fall Pattern):
• State 1 (Normal Motion): สภาวะการเคลื่อนไหวปกติ ค่า SMV อยู่ในช่วง 0.8G – 1.2G
• State 2 (Free Fall / Descent): ช่วงทิ้งตัวลง ค่าความเร่งลดลงอย่างรวดเร็ว (SMV < 0.6G) เป็นเวลาสั้นๆ (50–200 ms)
• State 3 (Impact Phase): จังหวะที่ร่างกายหรือแขนกระแทกพื้น เกิดแรงกระแทกสูงฉับพลัน (SMV > 2.5G – 3.0G)
• State 4 (Orientation Transition): การเปลี่ยนแปลงของมุมเอียงร่างกายอย่างมีนัยสำคัญ (Angular Velocity จาก Gyroscope > 200 deg/s)
• State 5 (Post-Fall Inactivity): ช่วงเวลาหลังการล้ม ผู้ป่วยส่วนใหญ่นักนอนนิ่งหรือไม่สามารถขยับตัวได้ ค่าความเร่งจะคงที่และผิดปกติจากแนวเดิมต่อเนื่องอย่างน้อย 2–5 วินาที
• State 6 (Fall Confirmed): เมื่อครบทุกเงื่อนไข ระบบจะคำนวณค่า Fall Confidence Score หากเกิน 75% จะยืนยันเหตุการณ์และส่งสัญญาณเตือนระดับ CRITICAL ไปยัง Dashboard ทันที
บทที่ 3วิธีดำเนินงานและออกแบบระบบ
บทนี้อธิบายรายละเอียดโครงสร้างสถาปัตยกรรม การออกแบบวงจรฮาร์ดแวร์ การจัดการพลังงาน สถาปัตยกรรมเฟิร์มแวร์บนไมโครคอนโทรลเลอร์ ESP32 การประมวลผลข้อมูล และการพัฒนาเว็บแอปพลิเคชันอย่างเป็นระบบ
3.1 ภาพรวมสถาปัตยกรรมระบบ (End-to-End Architecture)
ระบบประกอบด้วย 3 ส่วนหลักที่ประสานการทำงานร่วมกันอย่างสมบูรณ์ ได้แก่:
• Edge Layer (Wearable Smartwatch): อุปกรณ์สวมใส่ข้อมือที่ประมวลผลสัญญาณชีพและตรวจจับการหกล้ม ณ แหล่งกำเนิด พร้อมแสดงผลเบื้องต้นบนหน้าจอ LCD
• Cloud / Middleware Layer (Firebase & API): ระบบฐานข้อมูลคลาวด์ที่รับส่งข้อมูลแบบ Real-time และทำหน้าที่กระจายการแจ้งเตือน
• Application Layer (Next.js Nurse & Patient Dashboard): เว็บแอปพลิเคชันสำหรับแสดงผล ติดตามคิว และบริหารจัดการสภาวะวิกฤต

3.3 การจัดการพลังงานและความปลอดภัยของแบตเตอรี่
เนื่องจากอุปกรณ์ถูกออกแบบให้สวมใส่บนร่างกายผู้ป่วย ความปลอดภัยด้านพลังงานและความร้อนจึงเป็นสิ่งที่ต้องให้ความสำคัญสูงสุด วงจรภาคจ่ายไฟได้รับการออกแบบดังนี้:
• แบตเตอรี่ Lithium-Polymer (Li-Po) ขนาด 3.7V ความจุ 500–800 mAh พร้อมวงจรป้องกันในตัว (Built-in Protection Circuit Module: PCM ป้องกัน Overcharge/Overdischarge)
• วงจรชาร์จแบตเตอรี่ใช้ไอซี MCP73871 หรือ TP4056 ที่ตั้งค่ากระแสชาร์จคงที่ (Constant Current: CC) ไว้ที่ 200–300 mA เพื่อป้องกันแบตเตอรี่ร้อนเกินไปขณะชาร์จ
• ติดตั้ง Positive Temperature Coefficient (PTC Fuse) ขนาด 500mA ที่ขั้วบวกของแบตเตอรี่ เพื่อตัดวงจรอัตโนมัติเมื่อเกิดการลัดวงจร
• วงจรลดแรงดันแบบ Low Dropout Linear Regulator (LDO) จ่ายไฟ 3.3V ที่มีสัญญาณรบกวนต่ำ (Ultra-Low Noise) สำหรับเลี้ยงเซนเซอร์ PPG เพื่อความแม่นยำของสัญญาณแสง
3.4 สถาปัตยกรรมซอฟต์แวร์ฝังตัวบน ESP32 (Modular Firmware Architecture)
เฟิร์มแวร์บน ESP32 ได้รับการออกแบบเชิงโมดูลาร์ (Modular Design) เพื่อให้ง่ายต่อการบำรุงรักษาและป้องกันไม่ให้ฟังก์ชันหนึ่งส่งผลกระทบต่อฟังก์ชันอื่น ประกอบด้วยโมดูลหลัก 8 โมดูล:
📌 โครงสร้างโมดูลาร์ของเฟิร์มแวร์ (Modular Firmware Architecture)
• 1. BootDiagnosticManager: ดำเนินการทดสอบฮาร์ดแวร์ตัวเองเมื่อเปิดเครื่อง (Self-Test: ตรวจสอบ ESP32, I2C Bus, Sensor Address, OLED/LCD, Wi-Fi)
• 2. SensorManager: จัดการการอ่านค่าดิบจาก MAX32664 / MAX30102 ผ่าน I2C แบบ Non-blocking
• 3. MotionManager & FallDetector: รันสเตตแมชชีนตรวจจับการหกล้มจาก MPU-6050 และส่งค่า Motion Level ไปช่วยกรองสัญญาณ PPG
• 4. SignalQualityFilter: ตรวจสอบความถูกต้องของสัญญาณ (Contact Detection, SQI Index, Bandpass Filtering)
• 5. HealthProcessor: คำนวณค่า Heart Rate, SpO2, Skin Temp, Estimated BP และประเมินระดับความเสี่ยงทางสรีรวิทยา
• 6. DisplayManager: ควบคุมหน้าจอ LCD 1.28" แสดงผลค่าสุขภาพ สถานะ Wi-Fi และแบตเตอรี่ในรูปแบบกราฟิกที่อ่านง่าย
• 7. NetworkManager (WiFi & Reconnect): ควบคุมการเชื่อมต่อ Wi-Fi และมี Offline Buffer เก็บข้อมูลสำรองเมื่อสัญญาณหลุด
• 8. ApiClient: แปลงข้อมูลเป็น JSON Payload และส่งขึ้น Firebase / REST API ทุกๆ 3–5 วินาที

3.6 การออกแบบหน้าจอเว็บแอปพลิเคชัน (Next.js Dashboard & Queue System)
เว็บแอปพลิเคชันถูกออกแบบโดยยึดหลัก User-Centered Design แบ่งออกเป็น 2 มุมมองหลัก:
1. หน้าจอสำหรับพยาบาลและแพทย์ (Staff Monitoring Dashboard):
• แสดงรายชื่อผู้ป่วยทั้งหมดในคิวแบบ Live Cards เรียงลำดับความเร่งด่วนตามสี (แดง = วิกฤต, เหลือง = เตือน, เขียว = ปกติ)
• ระบบเสียงเตือน (Auditory Alarm) และแถบกระพริบทันทีเมื่อตรวจพบ SpO2 < 90%, HR > 120 BPM หรือ Fall Event
• กราฟแสดงแนวโน้มสัญญาณชีพย้อนหลัง (Vital Signs Historical Trend) เพื่อให้แพทย์ดูประกอบการตรวจรักษา
2. หน้าจอสำหรับผู้ป่วยและญาติ (Patient Mobile Web Card):
• แสดงหมายเลขคิวปัจจุบัน จำนวนคิวที่เหลือก่อนหน้า และห้องตรวจที่ต้องเข้า
• แสดงค่าสัญญาณชีพของตนเองอย่างเข้าใจง่าย (เช่น สถานะ: สุขภาพปกติ)
• มีปุ่มกดขอความช่วยเหลือฉุกเฉิน (Emergency Button) ที่เชื่อมต่อไปยังเคาน์เตอร์พยาบาลหรือโทรออกสายด่วน 1669 ทันที
บทที่ 4ผลการทดลองและการวิเคราะห์ผล

4.3 ผลการทดสอบด้านเครือข่าย ความหน่วง และพลังงาน
• ความหน่วงในการส่งข้อมูล (Latency): อัปเดตข้อมูลขึ้นสู่ Firebase และหน้าจอเว็บ Dashboard โดยเฉลี่ย 3.2 วินาที (อยู่ในเกณฑ์เป้าหมายไม่เกิน 3–5 วินาที)
• ระยะการส่งสัญญาณ Wi-Fi: ส่งข้อมูลได้อย่างเสถียรในระยะ 15–20 เมตร ในสภาพแวดล้อมอาคารโรงพยาบาล
• ระยะเวลาการใช้งานแบตเตอรี่ (Battery Life): แบตเตอรี่ Li-Po 500mAh สามารถทำงานต่อเนื่องในโหมดตรวจวัดและส่งข้อมูล Wi-Fi ได้ประมาณ 6–8 ชั่วโมงต่อการชาร์จ 1 ครั้ง ซึ่งครอบคลุมระยะเวลาการรอตรวจในแผนก OPD
บทที่ 5สรุปผล อภิปรายผล และข้อเสนอแนะ
5.1 สรุปผลการดำเนินงาน
โครงงาน "อุปกรณ์สวมใส่เพื่อการติดตามสุขภาพและเว็บแอปเช็คคิวผู้ป่วยนอก" ประสบความสำเร็จในการพัฒนาตามวัตถุประสงค์ทั้ง 4 ข้อที่ตั้งไว้ โดยสามารถสร้างอุปกรณ์ Smartwatch ต้นแบบที่ผสานเซนเซอร์ PPG (MAX32664 / MAX30102) และ IMU (MPU-6050) เข้ากับไมโครคอนโทรลเลอร์ ESP32 ได้อย่างสมบูรณ์
ระบบสามารถตรวจวัดและประเมินค่า Heart Rate, SpO2, Skin Temperature, และ Blood Pressure Estimation โดยมีค่าความคลาดเคลื่อนเฉลี่ยไม่เกิน ±3.5% เมื่อเทียบกับอุปกรณ์มาตรฐาน (ดีกว่าเกณฑ์ที่กำหนดไว้ไม่เกิน ±10%) อัลกอริทึม Multi-Stage Fall Detection และ Signal Quality Index สามารถกำจัดสัญญาณรบกวนและลดการแจ้งเตือนหลอกจากการเคลื่อนไหวทั่วไปได้อย่างมีประสิทธิภาพ และระบบ Web Application สามารถแสดงผลข้อมูลแบบเรียลไทม์พร้อมระบบจัดลำดับคิวและแจ้งเตือนวิกฤตได้ตามแผนงาน
5.2 อภิปรายผลและ Trade-offs ในการออกแบบ
• การประมวลผลบน Edge (ESP32) vs การประมวลผลบน Cloud: การใส่ฟิลเตอร์กรองสัญญาณและการรัน Fall State Machine บนบอร์ด ESP32 โดยตรง ช่วยลดภาระการส่งข้อมูลและการใช้แบนด์วิดท์เครือข่าย แต่แลกมาด้วยการใช้พลังงานประมวลผลของ MCU ที่เพิ่มขึ้นเล็กน้อย
• ความแม่นยำของเซนเซอร์ที่ข้อมือ vs ความสะดวกสบาย: การรัดสายนาฬิกาให้แน่นช่วยให้เซนเซอร์แนบสนิทกับผิวหนังและได้สัญญาณแสงที่ดีขึ้น แต่หากแน่นเกินไปอาจทำให้ผู้ป่วยรู้สึกไม่สบาย คณะผู้จัดทำจึงแก้ปัญหาด้วยการออกแบบฝาครอบกันแสงภายนอก (Ambient Light Shielding) เพื่อให้สามารถสวมใส่ในระดับความแน่นที่สบายข้อมือได้
• การแจ้งเตือนที่สมดุล (Alarm Fatigue Prevention): การใช้เกณฑ์สภาวะวิกฤตที่เคร่งครัดร่วมกับ Fall Confidence Scoring ช่วยลดภาระของพยาบาลไม่ให้เกิดภาวะ "ความล้าจากเสียงเตือน" (Alarm Fatigue) ทำให้บุคลากรให้ความสำคัญกับทุกการแจ้งเตือนที่เกิดขึ้นจริง
5.3 ข้อเสนอแนะและการพัฒนาต่อยอดในอนาคต
• การพัฒนาแผ่นวงจรพิมพ์เฉพาะทาง (Custom PCB Layout): ควรออกแบบและผลิตแผ่นวงจรพิมพ์แบบ 2-Layer หรือ 4-Layer ขนาดเล็กระดับเหรียญบาท เพื่อลดขนาดตัวเรือนให้อยู่ในระดับนาฬิกา Smartwatch เชิงพาณิชย์
• การประยุกต์ใช้ TinyML / Embedded AI: สามารถพัฒนาโมเดล Machine Learning ขนาดเล็กบน ESP32 (เช่น TensorFlow Lite for Microcontrollers) เพื่อเรียนรู้รูปแบบการเคลื่อนไหวเฉพาะบุคคลและเพิ่มความแม่นยำในการตรวจจับ Fall Detection ยิ่งขึ้น
• การผสานระบบเข้ากับฐานข้อมูลโรงพยาบาล (Hospital Information System: HIS): พัฒนา API เชื่อมต่อกับมาตรฐาน HL7 / FHIR เพื่อให้สามารถบันทึกสัญญาณชีพเข้าสู่เวชระเบียนอิเล็กทรอนิกส์ (EMR) ของโรงพยาบาลได้โดยตรง
• การเพิ่มระบบสลับโหมดพลังงาน (Deep Sleep & BLE Beacon): เพื่อยืดอายุการใช้งานแบตเตอรี่ให้สามารถใช้งานได้ต่อเนื่องยาวนานขึ้นเกิน 24–48 ชั่วโมง

ภาคผนวก ก: ผังวงจรและการต่อสายสัญญาณ (Schematic & Wiring)
ผังการเชื่อมต่อวงจรฮาร์ดแวร์ระหว่าง ESP32 กับโมดูลเซนเซอร์ MAX32664, MPU-6050, จอกลม LCD GC9A01 และระบบพลังงานแบตเตอรี่ Li-Po:
📌 ข้อกำหนดการเดินลายวงจรและการต่อสาย
• I2C Bus (SDA: GPIO 4, SCL: GPIO 5): ต่อขนานร่วมกันระหว่าง MAX32664 และ MPU-6050 โดยติดตั้งตัวต้านทาน Pull-up 4.7kΩ เข้ากับสายไฟเลี้ยง 3.3V
• SPI Bus (MOSI: GPIO 10, SCK: GPIO 8, CS: GPIO 9, DC: GPIO 3, RST: GPIO 2): เชื่อมต่อเข้ากับหน้าจอกลม Round LCD GC9A01 ขนาด 1.28 นิ้ว
• Battery Monitor (GPIO 1): ต่อผ่านวงจร Voltage Divider ตัวต้านทาน 100kΩ/100kΩ เพื่อลดทอนแรงดัน 3.7V–4.2V เข้าสู่อินพุต ADC (0–2.1V)
• Power Circuit: แบตเตอรี่ Li-Po 3.7V ผ่าน PTC Fuse 500mA เข้าโมดูลชาร์จ TP4056/MCP73871 และเรกูเลเตอร์ LDO 3.3V เลี้ยงวงจรทั้งหมด
