[18] (style=Normal) ABSTRACT
[19] (style=Normal) In modern healthcare administration within Outpatient Departments (OPD), a significant structural vulnerability is the "waiting gap"—the unmonitored duration between initial triage and physician consultation. When patients develop occult hemodynamically unstable conditions, such as occult shock (Shock Index > 0.9), acute ischemic stroke, or sudden cardiac arrest, a single static vital sign reading at admission fails to capture rapid physiological deterioration. Furthermore, conventional hospital queue systems operate statically and cannot adapt to fluctuating patient clinical severity.
[20] (style=Normal) This project introduces a comprehensive "Wearable Health Monitoring Smartwatch and Outpatient Queue Tracking Web Application" (Commlyzer-Health) leveraging Internet of Things (IoT) edge computing. The wearable device utilizes an ESP32 microcontroller integrated with optical Photoplethysmography (PPG) sensors (MAX32664 / MAX30102) for continuous Heart Rate (HR), Blood Oxygen Saturation (SpO2), and cuffless Blood Pressure (BP) estimation, complemented by an MPU-6050 6-axis IMU for sequential Multi-stage Fall Detection. Robust Signal Quality Index (SQI) and skin-contact detection filters are embedded to suppress motion artifacts. Telemetry data is encapsulated into JSON payloads and transmitted via Wi-Fi to a Firebase cloud database, powering a responsive real-time web dashboard engineered with Next.js, React, and Tailwind CSS. The system enables healthcare staff to continuously monitor patients, dynamically prioritize clinical queues, and receive instantaneous emergency alerts.
[21] (style=Normal) Experimental evaluations demonstrate that vital sign measurement errors remain strictly below ±3.5% compared to standard clinical benchmarks. The multi-stage fall detection algorithm successfully discriminates true falls from common daily activities (e.g., clapping, vigorous arm swinging, tossing, or rapid sitting) with a 0% false alarm rate in non-fall tests. Telemetry data exhibits an average latency of 3.2 seconds with automatic offline buffering upon network failure, and the device operates continuously for 6–8 hours per charge. This innovation delivers a scalable smart healthcare solution, mitigating clinical risks during outpatient waiting intervals and optimizing hospital workflows.

[88] (style=Normal) ในยุคปัจจุบัน การบริหารจัดการระบบบริการสาธารณสุขในโรงพยาบาล โดยเฉพาะแผนกผู้ป่วยนอก (Outpatient Department: OPD) ต้องเผชิญกับความท้าทายอย่างยิ่งจากจำนวนผู้เข้ารับบริการที่หนาแน่น ประกอบกับสังคมไทยและสังคมโลกได้ก้าวเข้าสู่ "สังคมผู้สูงอายุโดยสมบูรณ์" (Aged Society) ซึ่งส่งผลให้มีผู้ป่วยกลุ่มเปราะบางและผู้ป่วยโรคเรื้อรัง (Non-Communicable Diseases: NCDs) เช่น โรคความดันโลหิตสูง โรคเบาหวาน และโรคหัวใจ เข้ารับบริการในแต่ละวันเป็นจำนวนมหาศาล

[133] (style=Normal) 2.2 หลักการทำงานของเซนเซอร์เชิงแสง (Photoplethysmography: PPG)
[134] (style=Normal) Photoplethysmography (PPG) เป็นเทคนิคการตรวจวัดการเปลี่ยนแปลงของปริมาตรเลือดในหลอดเลือดฝอยใต้ผิวหนังโดยใช้แสง เซนเซอร์ PPG จะประกอบด้วยตัวเปล่งแสง (LEDs) สองความยาวคลื่น ได้แก่ แสงสีแดง (Red Light ความยาวคลื่น ~660 nm) และแสงอินฟราเรด (Infrared Light ความยาวคลื่น ~880–940 nm) ร่วมกับตัวตรวจจับแสง (Photodetector: PD)
[135] (style=Normal) หลักการทำงานอิงตามกฎของ Beer-Lambert Law เมื่อหัวใจบีบตัว ปริมาตรของเม็ดเลือดแดงในหลอดเลือดจะเพิ่มขึ้น ทำให้การดูดกลืนแสงเพิ่มขึ้น สัญญาณ PPG จึงประกอบด้วย 2 ส่วนหลักคือ: (1) ส่วนประกอบกระแสสลับ (AC Component) เกิดจากจังหวะการเต้นของหัวใจ และ (2) ส่วนประกอบกระแสตรง (DC Component) เกิดจากการดูดกลืนแสงของเนื้อเยื่อ กระดูก และเลือดที่อยู่นิ่ง
[136] (style=Normal) การคำนวณค่าความอิ่มตัวออกซิเจนในเลือด (SpO2) คำนวณจากอัตราส่วน Ratio of Ratios (R):
[137] (style=Normal) $$R = \frac{(AC_{Red} / DC_{Red})}{(AC_{IR} / DC_{IR})}$$
[138] (style=Normal) $$\text{SpO}_2 = A - B \times R$$
[139] (style=Normal) โดยที่ A และ B เป็นค่าสัมประสิทธิ์การปรับเทียบเชิงเส้น (โดยทั่วไป $A \approx 110, B \approx 25$ ขึ้นอยู่กับโมดูลเซนเซอร์และการออกแบบทางแสง)
[140] (style=Normal) 2.3 ความท้าทายของเซนเซอร์ Optical บริเวณข้อมือและการแก้ปัญหา
[141] (style=Normal) การตรวจวัดสัญญาณ PPG บริเวณข้อมือ (Wrist-based PPG) มีความท้าทายและความซับซ้อนสูงกว่าการวัดที่ปลายนิ้ว (Finger-clip) อย่างมาก เนื่องจากบริเวณข้อมือมีชั้นผิวหนังที่หนากว่า มีเส้นเอ็น กระดูก และหลอดเลือดอยู่ลึกกว่า อีกทั้งข้อมือเป็นส่วนที่มีการขยับและเคลื่อนไหวอยู่ตลอดเวลา
[142] (style=Normal) 
[143] (style=Normal) 2.4 ทฤษฎีการตรวจจับการหกล้ม (Multi-Stage Fall Detection Algorithms)
[144] (style=Normal) การตรวจจับการหกล้ม (Fall Detection) ถือเป็นฟังก์ชันความปลอดภัยสูงสุดของระบบ อุปกรณ์สวมใส่โดยทั่วไปที่ใช้เพียง "เกณฑ์ความเร่งเดียว" (Single Threshold Acceleration > 2.5G) จะก่อให้เกิดการเตือนผิดพลาด (False Positives) เป็นจำนวนมาก เช่น เมื่อผู้ใช้ตบมือ โยนของ นั่งลงอย่างแรง หรือแกว่งแขนกระแทกโต๊ะ
[145] (style=Normal) ในโครงงานนี้ คณะผู้จัดทำได้ออกแบบอัลกอริทึมการตรวจจับการหกล้มแบบลำดับขั้นตอนต่อเนื่อง (Sequential Multi-Stage State Machine) ร่วมกับชุดตรวจวัดความเร่งและไจโรสโคป MPU-6050 โดยคำนวณค่าขนาดความเร่งรวม (Signal Magnitude Vector: SMV):
[146] (style=Normal) $$\text{SMV} = \sqrt{a_x^2 + a_y^2 + a_z^2}$$
[147] (style=Normal) ลำดับสเตตแมชชีนของการหกล้มจริง (Genuine Fall Pattern):
[148] (style=Normal) • State 1 (Normal Motion): สภาวะการเคลื่อนไหวปกติ ค่า SMV อยู่ในช่วง 0.8G – 1.2G
[149] (style=Normal) • State 2 (Free Fall / Descent): ช่วงทิ้งตัวลง ค่าความเร่งลดลงอย่างรวดเร็ว (SMV < 0.6G) เป็นเวลาสั้นๆ (50–200 ms)
[150] (style=Normal) • State 3 (Impact Phase): จังหวะที่ร่างกายหรือแขนกระแทกพื้น เกิดแรงกระแทกสูงฉับพลัน (SMV > 2.5G – 3.0G)
[151] (style=Normal) • State 4 (Orientation Transition): การเปลี่ยนแปลงของมุมเอียงร่างกายอย่างมีนัยสำคัญ (Angular Velocity จาก Gyroscope > 200 deg/s)
[152] (style=Normal) • State 5 (Post-Fall Inactivity): ช่วงเวลาหลังการล้ม ผู้ป่วยส่วนใหญ่นักนอนนิ่งหรือไม่สามารถขยับตัวได้ ค่าความเร่งจะคงที่และผิดปกติจากแนวเดิมต่อเนื่องอย่างน้อย 2–5 วินาที
[153] (style=Normal) • State 6 (Fall Confirmed): เมื่อครบทุกเงื่อนไข ระบบจะคำนวณค่า Fall Confidence Score หากเกิน 75% จะยืนยันเหตุการณ์และส่งสัญญาณเตือนระดับ CRITICAL ไปยัง Dashboard ทันที
[154] (style=Normal)

[204] (style=Normal) ระบบสามารถตรวจวัดและประเมินค่า Heart Rate, SpO2, Skin Temperature, และ Blood Pressure Estimation โดยมีค่าความคลาดเคลื่อนเฉลี่ยไม่เกิน ±3.5% เมื่อเทียบกับอุปกรณ์มาตรฐาน (ดีกว่าเกณฑ์ที่กำหนดไว้ไม่เกิน ±10%) อัลกอริทึม Multi-Stage Fall Detection และ Signal Quality Index สามารถกำจัดสัญญาณรบกวนและลดการแจ้งเตือนหลอกจากการเคลื่อนไหวทั่วไปได้อย่างมีประสิทธิภาพ และระบบ Web Application สามารถแสดงผลข้อมูลแบบเรียลไทม์พร้อมระบบจัดลำดับคิวและแจ้งเตือนวิกฤตได้ตามแผนงาน
[205] (style=Normal) 5.2 อภิปรายผลและ Trade-offs ในการออกแบบ
[206] (style=Normal) • การประมวลผลบน Edge (ESP32) vs การประมวลผลบน Cloud: การใส่ฟิลเตอร์กรองสัญญาณและการรัน Fall State Machine บนบอร์ด ESP32 โดยตรง ช่วยลดภาระการส่งข้อมูลและการใช้แบนด์วิดท์เครือข่าย แต่แลกมาด้วยการใช้พลังงานประมวลผลของ MCU ที่เพิ่มขึ้นเล็กน้อย
[207] (style=Normal) • ความแม่นยำของเซนเซอร์ที่ข้อมือ vs ความสะดวกสบาย: การรัดสายนาฬิกาให้แน่นช่วยให้เซนเซอร์แนบสนิทกับผิวหนังและได้สัญญาณแสงที่ดีขึ้น แต่หากแน่นเกินไปอาจทำให้ผู้ป่วยรู้สึกไม่สบาย คณะผู้จัดทำจึงแก้ปัญหาด้วยการออกแบบฝาครอบกันแสงภายนอก (Ambient Light Shielding) เพื่อให้สามารถสวมใส่ในระดับความแน่นที่สบายข้อมือได้
[208] (style=Normal) • การแจ้งเตือนที่สมดุล (Alarm Fatigue Prevention): การใช้เกณฑ์สภาวะวิกฤตที่เคร่งครัดร่วมกับ Fall Confidence Scoring ช่วยลดภาระของพยาบาลไม่ให้เกิดภาวะ "ความล้าจากเสียงเตือน" (Alarm Fatigue) ทำให้บุคลากรให้ความสำคัญกับทุกการแจ้งเตือนที่เกิดขึ้นจริง
[209] (style=Normal) 5.3 ข้อเสนอแนะและการพัฒนาต่อยอดในอนาคต
[210] (style=Normal) • การพัฒนาแผ่นวงจรพิมพ์เฉพาะทาง (Custom PCB Layout): ควรออกแบบและผลิตแผ่นวงจรพิมพ์แบบ 2-Layer หรือ 4-Layer ขนาดเล็กระดับเหรียญบาท เพื่อลดขนาดตัวเรือนให้อยู่ในระดับนาฬิกา Smartwatch เชิงพาณิชย์
[211] (style=Normal) • การประยุกต์ใช้ TinyML / Embedded AI: สามารถพัฒนาโมเดล Machine Learning ขนาดเล็กบน ESP32 (เช่น TensorFlow Lite for Microcontrollers) เพื่อเรียนรู้รูปแบบการเคลื่อนไหวเฉพาะบุคคลและเพิ่มความแม่นยำในการตรวจจับ Fall Detection ยิ่งขึ้น
[212] (style=Normal) • การผสานระบบเข้ากับฐานข้อมูลโรงพยาบาล (Hospital Information System: HIS): พัฒนา API เชื่อมต่อกับมาตรฐาน HL7 / FHIR เพื่อให้สามารถบันทึกสัญญาณชีพเข้าสู่เวชระเบียนอิเล็กทรอนิกส์ (EMR) ของโรงพยาบาลได้โดยตรง
[213] (style=Normal) • การเพิ่มระบบสลับโหมดพลังงาน (Deep Sleep & BLE Beacon): เพื่อยืดอายุการใช้งานแบตเตอรี่ให้สามารถใช้งานได้ต่อเนื่องยาวนานขึ้นเกิน 24–48 ชั่วโมง
